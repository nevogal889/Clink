# CLAUDE.md: Clink operating manual

Read this first in every session. It's short on purpose; the docs it points to hold the detail.

## What Clink is

A home-screen widget with a small companion app, on iOS and Android, for drink breaks with close friends.
Drink snaps land on friends' widgets for 24 hours; flares ask "who joins?" for coffee, matcha, tea or a smoothie, and friends answer "I'm in", or "Bring me one" to send their saved order.
A private drink and water tracker and a private XP level sit alongside. Nobody is ever shown declining, and counts and levels are never shared.

## The CEO's 10 guidelines (non-negotiable)

1. Unique design that doesn't look AI-generated: no cream + serif + terracotta, no purple gradients, no decorative emoji, no rounded cards everywhere.
2. Drink pictures for each category are stylish and clear.
3. Every word reads as written by a person.
4. UX is the top priority: very easy to use and navigate.
5. **No quiet hours.** Not a setting, not a column, not a server check.
6. **No visible invite link or "Invite link" label.** Share buttons only (WhatsApp, Messages, More).
7. Top 10 drinks in every category.
8. The fourth category is **"Smoothie & Juice"**.
9. **XP is private.** Rewards engagement (invites, joining flares, drink runs). Nobody else sees it; no leaderboards.
10. Ship on **Android (Google Play)** as well as iOS.

## Who decides

- The Head of Product and the CTO decide everything else. Decide, write the reason in one line in the right doc, move on.
- Only questions that change scope, cost money, or carry legal or brand risk go to the CEO. Add them to `PRD.md` section 8 (one merged list), each with a recommendation. Never ask the CEO in a code comment or a PR.
- Never invent facts you can't know (prices, quotas, versions released after your knowledge). Write "latest stable at build time, minimum X" or "verify before purchase".

## Stack

- **App:** Expo + React Native, TypeScript strict, Expo Router, New Architecture. Latest stable Expo SDK at build time, minimum SDK 54.
- **Widgets:** native only. iOS: Swift, WidgetKit, App Intents, ActivityKit (Live Activity), a Notification Service Extension, via `@bacons/apple-targets` (pinned). Android: Kotlin, Jetpack Glance, WorkManager, our own FCM service. No JS runs in the background.
- **Backend:** Supabase (Postgres with RLS, Auth, Storage, Edge Functions on Deno, pg_cron). Direct APNs and FCM from edge functions.
- **Builds:** EAS Build, Submit, Update. `ios/` and `android/` are generated by prebuild and never committed.
- **Minimum OS:** iOS 17.2, Android 8.0 (API 26).
- **Analytics:** first-party `app_events` only. Errors: Sentry with no PII.

## Coding conventions

- **Words:** every user-facing string comes from a `COPY.md` key through the generated string table (`scripts/gen-strings`). No string literals in TS, Swift or Kotlin UI code. If a string is missing, add the key to `COPY.md` first.
- **Catalog:** drink ids are `category.slug` from `COPY.md` 2; categories are `coffee`, `matcha`, `tea`, `smoothie_juice`, plus `water` for logs only. Water is never a flare type and never a usual 3 slot.
- **Shared rules live once** in `packages/shared` (zod schemas, PRD text limits, XP values, the Automatic rule, event names) and are copied to functions by script. Swift and Kotlin ports of the Automatic rule are tested against the same fixtures.
- **Database:** one migration per change, never edited after merge, backwards compatible with the last two store builds. RLS on every `public` table, with allow and deny pgTAP tests. Internal functions, server-only tables and moderation views go in the `private` schema. Policies qualify every column and use `(select auth.uid())`.
- **Server rules:** the server is the only writer of shared truth. Edge functions read as the user (RLS applies) and write as the service role through `private` functions. The caller always comes from the verified JWT or widget token, never from a parameter. The server owns time (`private.app_now()`); clients send durations and a tap time.
- **Privacy:** no free text, photos, phone numbers or contact data in logs, analytics or Sentry. Never set a Sentry user id. Secrets go where `ARCHITECTURE.md` 8.5 says; nothing secret in `EXPO_PUBLIC_*` or `app.config` `extra`.
- **No-shame rules:** never record or show a decline, "seen", a viewer count or an ignored flare. Flares expire quietly.
- **Platforms:** every feature ships on iOS and Android together, in both widget sizes where it applies.
- **Docs:** plain, specific, short sentences for engineers. No marketing words, no em-dash asides, no "not X but Y". Mark unconfirmed facts **(verify)**.
- **Git:** commit only when asked. Branch off `main` first.

## Definition of done

A change is done when all of these are true:
1. **Acceptance criteria** for the feature in `PRD.md` pass, and the tap budget (PRD 3.0) still holds.
2. **Tests** are in CI and green: unit (Jest) and component tests; `deno test` for functions (happy path, every limit, every refusal); pgTAP allow and deny for every policy touched and `permission denied` for every new `private` function; widget fixtures decode in TS, Swift and Kotlin; a Maestro flow or a QA manual script for every flow touched.
3. **Both platforms:** works on iOS and Android, app and widget, light and dark, largest text size, offline, and every empty, loading, error and denied-permission state (`DESIGN.md` 8 rule 12).
4. **Accessibility:** every control has a screen-reader label from `COPY.md` 4.26; contrast and target sizes per `DESIGN.md` 7.
5. **Copy:** all text from `COPY.md` keys, no hard-coded strings, no banned words (`COPY.md` 1.3).
6. **Privacy:** no other user's API response gains groups, XP, counts, water, phone numbers or non-mutual names; new data has a retention row in `ARCHITECTURE.md` 4.8 and is covered by account deletion and the store declarations (`PRD.md` 7).
7. Docs updated if behaviour changed.
