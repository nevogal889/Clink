Shared JSON fixtures read by the TS, Swift and Kotlin tests. Hand-maintained data; edit the JSON directly.

- `automatic-rule.json`: Automatic audience cases T22 to T33 (`docs/QA_PLAN.md` 6.3) plus edges A1 to A8. Each case has the tap instant (`at`), the sender's `timeZone`, the same moment as `local` (ISO weekday, hour, minute), the widget-state `settings` and `groups`, and `expected` (a group id or `"everyone"`). A port may read `local` directly or compute it from `at` and `timeZone`.
- `widget-states/W01-…json` to `W22-…json`: one fixture per widget state in `docs/QA_PLAN.md` 4.1. Each holds `now`, `timeZone`, the widget `config` (audience), the server `state` (decodes with `widgetStateSchema`), the widget-local `local` state (or null) and `expect.small` / `expect.medium`: the view `resolveWidgetView()` must return for that size (null where QA marks the size n/a). Expected views are partial: only the listed fields are checked.
- `widget-states/invalid/*.json`: documents the server must never send (`widgetStateSchema`, strict, refuses all of them). Decoders (`widgetStateReadSchema`, the Kotlin and Swift widgets, the app's preview host) reject every one except `xp-field.json`: old and new `v`, unknown state, missing fields, a water flare, an over-budget name, a timestamp without a zone. `xp-field.json` is only an unknown key, so a decoder accepts it and drops the key, and the XP never reaches the widget (ARCHITECTURE.md 3.1, add fields only). On a rejected document the widget keeps its last good state (`QA_PLAN.md` ST8).
